# AWS検証記事の図と証跡

ユーザー指定の執筆要件として、以後のAWS検証記事にも適用する。

- 検証の主要工程ごとに、設定・実行・結果が分かる証跡を示す。画面キャプチャはAWSコンソールや実際のコマンドプロンプト・ターミナルの実画面を使う。実画面がない場合、保存したコマンド出力・API応答・ログはコピーできるコードブロックや表で掲載する。出力をHTML等で整形して画像化し、キャプチャ画像の代わりにしない。
- 実画面のスクリーンショットがある箇所では、同じ出力をコードブロックで重複掲載しない。実行・入力するコマンドはコピーできるコードブロックとして掲載する。画面に含まれない設定ファイルや出力は必要に応じてテキストで補う。
- ターミナル画像の直前には、画像内で実際に実行したコマンドそのものをコードブロックで掲載する。変数名、引数、抽出・マスクのパイプ処理も照合する。EC2内のLinux操作と、Windowsから履歴や保存ファイルを取得する操作を明確に区別し、異なる操作の結果画像として見せない。
- 指定された節に図を追加する場合は、その節の説明に合わせて新しく作る。全体構成図の再掲で済ませない。ラベル・矢印・枠の重なりを確認する。
- 見出し・本文・図では「Amazon Linux 2023」と書き、「AL2023」と略さない。実際のパッケージ名やコード識別子は変更しない。
- ログ項目や検証用IDは、目的、付与する処理、値の具体例、照合方法を説明する。内部の略号を説明なしで読者へ提示しない。
- 出力の抜粋・要約・マスク箇所は明記し、過去の検証状態を現在の稼働状態として示さない。保存済み出力を表示した画面を、新たにコマンドを実行した画面として扱わない。データや検証結果を捏造しない。
- 個人情報、アカウントID、不要な公開IP等は画像・配布ファイルからマスクし、原本は非公開の証跡として保管する。
- AWS検証の端末操作とブラウザはNAB7を使う。Inspironで実施しない。
- 本文に挿入した全画像の読み込み、スマホ幅とPC幅の表示、拡大表示を確認してから完了を報告する。
- 公開の明示指示がない下書きは未公開のまま更新する。

- コマンドの見出しは「実行したコマンド」とする。設定内容・料金の説明にも実画面を用意し、画像で見る項目、設定値の意味、費用の単位・数量・条件を説明する。リソース削除の前に、必要な実画面の撮影と証跡原本の退避・照合・保存を完了する。
